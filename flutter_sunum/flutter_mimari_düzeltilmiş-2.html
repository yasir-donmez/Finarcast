MİMARİ GENEL BAKIŞ

Flutter Neden Farklı Bir Mimari Sunar?

Flutter, klasik "köprü" mimarisini tamamen terk ederek kendi render motorunu taşıyan, platformdan bağımsız bir yapı kurar. Bu sayede piksel düzeyinde kontrol elde edilir.

🧱

Her Şey Widget

Flutter'da ekranda gördüğümüz her yapı aslında bir widget'tır. Butonlar, metinler, boşluklar ve animasyonlar aynı mimari yapı altında yönetilir. Bu yaklaşım kod tekrarını azaltır ve büyük projelerde yönetilebilirliği artırır.

🎨

Kendi Render Motoru

Flutter kendi grafik motorunu kullandığı için Android ve iOS arasında tasarım farkı minimum seviyeye iner. Impeller ile birlikte shader optimizasyonları geliştirilmiş ve özellikle animasyon performansı ciddi şekilde artırılmıştır.

⚡

JIT + AOT Dart

Hot Reload sayesinde geliştirici uygulamayı kapatmadan değişiklikleri anında görebilir. Release modunda ise Dart kodu doğrudan makine koduna çevrilir ve native uygulama performansı elde edilir.

Impeller (Yeni Motor)

Skia'nın runtime shader derleme problemini ortadan kaldırır. Shaderlar derleme zamanında hazırlanır → jank-free ilk frame. Flutter 3.10+ varsayılan.

Skia vs Native

Native iOS/Android her platformun kendi render stack'ini kullanır. Flutter ise aynı Skia/Impeller'ı her platformda çalıştırır → pixel-perfect tutarlılık.

DART VM & CONCURRENCY

Dart VM, Isolate ve Platform Channel

🧵 Isolate Modeli

Dart thread'leri bellek paylaşmaz; her Isolate kendi heap'ine sahiptir. Race condition imkansız. UI Isolate ↔ Background Isolate mesajlaşma ile haberleşir. Flutter'da UI her zaman main isolate'tedir.

🌉 Platform Channel

Native API'ye erişmek gerektiğinde MethodChannel / EventChannel kullanılır. Dart ↔ Kotlin/Swift arası seri mesaj geçişi. Kamera, GPS, Bluetooth bu yolla erişilir.

⚙️ AOT vs JIT

JIT (debug): Hot reload mümkün, VM bytecode çalışır, daha yavaş.

AOT (release): Makine koduna derlenir, startup hızlıdır, minimum memory footprint. React Native'in JS engine'inden belirgin şekilde daha hızlı.

🔀 Flutter vs RN Bridge

React Native, JS ↔ Native arasında async JSON köprüsü kullanır; bu "bridge" bottleneck yaratabilir. Flutter 3.0'dan itibaren FFI (dart:ffi) ile C/C++ doğrudan çağrılabilir, köprü maliyeti sıfıra iner.

BİLGİ KONTROLÜ
S1 Flutter'ın render motoru diğer cross-platform framework'lerden nasıl ayrışır?
A Her platformun native widget'larını JavaScript köprüsüyle kullanır ve platform uyumunu maksimize eder
B Kendi grafik motoruyla (Skia/Impeller) tüm pikselleri çizerek platform bağımsız tutarlılık sağlar
C WebView içinde HTML/CSS render ederek çoklu platform desteğini tek kod tabanıyla karşılar
D Platforma özgü API'leri derleyerek native uygulamanın aynı ikili dosyasını üretir
S2 Flutter'da üç ağaç yapısının (Widget, Element, RenderObject) rolü nedir?
A Widget ağacı GPU'ya yazarken Element ağacı state'i tutar, RenderObject ağacı ise konfigürasyon depolar
B Her üç ağaç da aynı veriyi farklı formatlarda tutarak yedeklilik ve hata toleransı sağlar
C Widget konfigürasyonu tanımlar; Element yaşam döngüsünü yönetir; RenderObject layout ve boyama işlemini yapar
D Widget animasyonları işlerken Element tema verilerini tutar, RenderObject ise platform kanalını yönetir
S3 Dart'ın Isolate modelinin React Native mimarisine göre temel avantajı nedir?
A JavaScript'e kıyasla daha az kaynak tüketir çünkü tek thread üzerinde tüm işlemleri sırayla yürütür
B Bellek paylaşımlı thread'ler sayesinde veriyi kopyalamadan paralel işlem yapabilir ve hız kazanır
C Izole'lar bellek paylaşmaz; bu race condition riskini ortadan kaldırır ve JS köprüsüne gerek duymadan AOT derleme ile native performans sağlar
D Platform kanalı üzerinden senkron çağrı yaparak native API gecikmesini tamamen ortadan kaldırır
